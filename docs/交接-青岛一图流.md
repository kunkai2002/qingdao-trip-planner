## 一、这是什么

把一份 713 行的单文件 HTML（原件备份在
`D:\kun-workspace\backup\20260730-qingdao-map-source\`）重构成的**行程工作台**。

### 🔥 2026-08-01 大改版：主对象从「点位」换成「旅行」

## 三、装成安卓 App（给使用者看的部分）

**用安卓手机的 Chrome 打开线上网址 → 菜单（右上⋮）→「安装应用」**，
或在应用内 **设置 → 装到手机上 → 安装到手机**。

装完之后：桌面有独立图标、全屏没有地址栏、在最近任务里是独立一个 App、
**而且会自动更新**（改完 push 就行，不用重装）。

### 为什么这样就够了

安卓上「已安装的 PWA」本来就是一个正经的启动器应用。之前我一直在讲的
**「7 天不用就清数据」是 Safari 的规则，安卓不适用**。安卓这边的风险是
「系统空间不足时清理」，对应的解法是 `navigator.storage.persist()`，
应用启动时和安装成功时都会申请一次，设置页会显示有没有拿到。

### 如果确实需要一个 .apk 文件

**已经构建过、已经能下载了。**固定链接（手机浏览器直接开）：

```
https://github.com/kunkai2002/qingdao-trip-planner/releases/latest/download/qingdao-trip-planner.apk
```

这个链接永远指向最新一次发布，1.26 MB。装的时候安卓会问「是否允许安装未知来源应用」。

## 五、🔴 铁律（改之前一定要看）

### 0. 网格轨道一律 `minmax(0, 1fr)`，永远不要写 `1fr`
`1fr` 等于 `minmax(auto, 1fr)`，**内容的最小宽度会把轨道顶开**。
实测：390px 宽的手机上量到 **532px 的列**；390px 高的横屏里量到 **492px 高的工作区**。
两次都被 `overflow: hidden` 藏住了 —— 页面看起来完全正常，只是右边/下边够不到。
`.shell` 的行列和 `.work` 的行都必须写 `minmax(0, 1fr)`。

### 0.3 🔥 一切「永远在动」的效果，一律用**有没有鼠标**来关
`@media (hover: hover) and (pointer: fine)`。**手机发烫就是这个**：

| 元凶 | 为什么贵 |
| --- | --- |
| `.ambient` 四层 ~390px + `blur(72px)` + 父层 `mix-blend-mode: soft-light` + 无限 transform | 模糊没法只靠合成器，混合模式还强制读回底下所有东西 → **每帧重栅格 4 张大图并重合成整张地图**。也是「闪几下」的元凶：瓦片一张张到位时，这一叠混合层反复重合成 |
| `.glass--drift` 的 `rimDrift` / `sheenDrift` | 动的是**注册过的自定义属性**喂给 conic-gradient → 只能重绘不能合成，而且就动在带 `backdrop-filter` 的元素上 |
| `.route-line--flow` 的 `dashFlow` | 每帧重绘 Leaflet 整个 SVG overlay pane |
| `.userpos::after` 的 `userPulse` | 点过「定位」之后**永不停**，正好是在外面走、最该省电的时候 |
| Leaflet 自带的 `.leaflet-tile { mix-blend-mode: plus-lighter }` | 淡入用的，**每张瓦片一次读回**，屏幕上有 ~15 张 |

现在这些全部关在鼠标后面，`<Ambient/>` 在触屏上**根本不挂载**（CSS 里另有
`@media (pointer: coarse) { .ambient { display:none } }` 兜底），触屏还关掉瓦片淡入、
`keepBuffer` 3→1、`updateWhenIdle` 打开。桌面观感不变。

🔴 **量过、并且刻意没做**：JS 根本不是瓶颈 —— `buildTimeline` 3.3µs、`runSearch` 1.2µs、
五天全算 9.6µs、优化 27µs，DOM 709 个节点。**发热全在 GPU 合成，不在 JS。**
所以没有去做 zustand 选择器改造：那是拿风险换一个量不到的收益。

### 0.5 🔥 Service Worker 里的 `fetch()` **不等于**走网络
导航处理器本来就写着「network-first」，但 SW 里的 `fetch(request)` **依然可能由浏览器
HTTP 缓存作答**，而 GitHub Pages 给 index.html 发的是 `max-age=600`。
结果就是：**部署完十分钟内，回访用户拿到的还是旧 HTML、旧 bundle**。
实测抓到过：线上 HTML 指向 `index-DIIUJ6ZP.js`，页面实际跑的是上一版 `index-Bvia5BYb.js`。
正解是导航请求必须 `fetch(new Request(url, { cache: 'reload' }))`。
**「改完 push 就生效」这句话，全靠这一行。**

### 0.7 开发机上的 `prefers-reduced-transparency` 会骗你
这台 Windows 关掉了「透明效果」，于是 `prefers-reduced-transparency: reduce` 命中，
`.ambient` 是 `display:none`、`.glass` 的 `backdrop-filter` 是 `none` ——
**桌面上从头到尾就没显示过毛玻璃和环境光**。手机没有这个开关，跑的是完整版。
所以「桌面上很流畅」完全不能推断手机；要判断性能，**先确认这两个媒体特性的实际取值**。

### 1. 样式导入顺序有意义
`main.jsx` 必须 **tokens → glass → base → leaflet-theme → workspace**。
`.glass{position:relative}` 和 `.panel{position:absolute}` 权重相同，
**只有源码顺序决定胜负**。顺序错了面板会变成 relative 跑到左上角。
`workspace.css` 排最后是因为它有几条规则专门把某个表面**从玻璃手里拿回来**
（`.panel--solid` 让手机上的地点详情 sheet 变成不透明）。

### 1.5 `haversine()` 返回公里，不是米
行程、`transit.js`、`optimize.js`、`formatDistance` 全部说**米**。
把它当米读会让横跨青岛的一天显示成「7 m」，**而且不会有任何报错**。
本轮真的踩到了，靠在浏览器里读渲染结果才发现。新代码一律用 `haversineM()`。

### 2. 改玻璃底色，必须同步检查 `@supports` 降级块
控件是**深色玻璃**、文字是**浅色**。`glass.css` 里
`@supports not (backdrop-filter)` 的降级如果写成白色，
**不支持 backdrop-filter 的浏览器会整个 UI 白底白字**（已经踩过一次）。

### 3. 文字颜色按实测对比度选，不要凭手感
最坏情况＝最薄的 `--g-tint-b`(0.80) 叠在白色地图高光上。
现值：ink-1 8.5 / ink-2 5.4 / ink-3 4.7 / accent 4.9，全部过 WCAG AA。
**`--g-tint-b: 0.80` 是承重的**，为了更透而调低会静默破坏次级文字。

### 4. 图钉尺寸和 `iconAnchor` 必须一起改
图钉是 24×24 方块转 -45°，半对角线 16.97，尖端落在 (14, 29)，
所以 `iconSize [28,32]`、`iconAnchor [14,29]`。
**改一个不改另一个，49 个点会全部偏离真实坐标。**

### 5. 跨图钉层级只能用 `setZIndexOffset()`
Leaflet 把 z-index 内联写在父层 `.leaflet-marker-icon` 上（**由纬度推导**），
`.pin` 上的 `z-index` **永远不起作用**。偏南的图钉会盖住选中的偏北图钉。

### 6. 坐标：WGS-84 → GCJ-02 只转一次
种子点位是 WGS-84，首次加载转一次。
**localStorage 里存的已经是转换后的，绝不能再转第二次。**
定位（`navigator.geolocation`）拿到的是 WGS-84，**必须过 `wgs2gcj` 再用**，
否则蓝点偏几百米。

### 7. 搜索：先比文字，再看图层
`lib/search.js`。图层开关只决定**画不画**，不参与匹配 ——
否则「上次关掉的图层」会让今天的搜索静默返回 0 且不说明原因。
被图层挡住的命中要显示出来并提供一键恢复。

### 8. 不要用 `AnimatePresence mode="wait"` 闸门内容切换
它让正确性依赖动画完成，还给每次切面板加延迟。
内容切换用 keyed 元素 + fade-in；`mode="wait"` 只用于换单个图标这类纯装饰。

### 9. 验证时：帧冻结会骗你（已踩四次）
`getBoundingClientRect()` 在动画进行中会量到中间值
（44px 量成 41px、opacity 量成 0.11），`AnimatePresence` 退场会让元素多留一会儿，
程序化 `scrollLeft` 不触发 scroll 事件。
**先注入 `transform:none!important;opacity:1!important` 再量；
状态一律看 `window.__store.getState()`，不要看 DOM 里还在不在。**

DEV 下有三个把手专供验证：`window.__map`、`window.__mapApi`、`window.__store`
（`import.meta.env.DEV` 保护，不会进线上产物）。

### 10. 改代码只用 Edit/Write
禁用 PowerShell `Get-Content | Set-Content`（会毁非 ASCII 字符，
`-Encoding utf8` 还塞 BOM）。确实要按字节改就用
`[IO.File]::WriteAllText($p,$t,(New-Object Text.UTF8Encoding($false)))`。
自查扫 `�`，**别扫 `??`**（JS 空值合并会大量误报）。

## 六、关键设计决定（以及为什么）

| 决定 | 原因 |
| --- | --- |
| 控件用**深色玻璃**，两个主题都是 | 浅色玻璃叠在浅色地图上完全没有对比，折射/轮廓光全看不见，成品就是「白色圆角塑料片」。深色玻璃自带对比，因为地图永远比它亮。**主题开关因此只控制地图**。 |
| 图钉**浅底彩色图标**，只有选中/路线站点/移动中才填充 | 49 个高饱和色块会跟地图抢注意力。让颜色有意义：响度跟随相关性。 |
| **自写像素网格聚合**，不用 leaflet.markercluster | 它会接管 marker 所有权，打烂现有的 reconcile-by-id 与图标状态逻辑。 |
| 标签**限量**（zoom≥14、最多 14 个、带碰撞规避） | 49 个名字同时出现就是一堵文字墙。 |
| 点位默认**不可拖动**，要按「调整位置」武装 | 原本全部 `draggable:true`，拖点会抢掉地图平移，还容易误移。 |
| 弹窗自己实现，不用 `window.confirm/prompt` | 原生弹窗无法设计、无法翻译，且会打破玻璃质感。 |
| 手机 sheet **固定高度再平移**，不是内容自适应 | 多档位（peek/half/full）只有这样才做得出来。地图应用里**面板背后就是内容**。 |
